# 决策点摘要模板（意图确认清单）

> `/sddl:confirm` 开场展示的摘要。让用户先有全局观，再逐项 clarify。从 spec 的 decision_points 自动生成。

## 生成规则

1. 按类别分组：契约类 / 行为类 / 约束类 / 实现类
2. 每类标注确认要求：契约/行为/约束 = 必须确认；实现 = 可授权
3. 每个决策点附影响说明（"若选 X 则 Y"）
4. 顶部显示总数 + 预计时间（每决策点约 30 秒）

## 模板

```
┌─────────────────────────────────────────────────────┐
│  Spec 意图确认清单（<domain>-service v<version>）     │
│  共 N 个决策点：契约 X / 行为 Y / 约束 Z / 实现 W      │
│  预计 N×30 秒完成                                    │
│                                                     │
│  【契约类】必须确认（改契约影响最大）                   │
│  □ DP-001 <topic>：建议 <default>（备选 <alts>）     │
│      → 影响：<impact>                                │
│  □ DP-002 <topic>：建议 <default>                    │
│      → 影响：<impact>                                │
│                                                     │
│  【行为类】必须确认                                   │
│  □ DP-003 <topic>：建议 <default>                    │
│      → 影响：<impact>                                │
│                                                     │
│  【约束类】必须确认                                   │
│  □ DP-004 <topic>：建议 <default>                    │
│      → 影响：<impact>                                │
│                                                     │
│  【实现类】可授权（默认授权 AI 决定）                  │
│  □ DP-005 <topic>：建议 <default>                    │
│      → 影响：<impact>                                │
│                                                     │
│  操作：逐项选择 确认 / 修改 / 授权 AI                  │
│  全部处理后 → 签署确认记录，spec 冻结                  │
└─────────────────────────────────────────────────────┘
```

## 影响说明示例

| 决策点 | 影响说明 |
|--------|---------|
| token 有效期 | 若选 7 天：用户 7 天后需重新登录；若选 1 天：更安全但频繁重登 |
| 失败尝试上限 | 若选 3 次：更安全但误锁风险高；若选 10 次：误锁少但暴力破解窗口大 |
| JWT 签名算法 | RS256 非对称适合多服务；HS256 对称实现简单但密钥分发难 |
| 密码规则 | 若 8-64 位含字母数字：平衡；若强制特殊字符：更安全但用户反感 |

## 确认交互（clarify）

每个决策点一个 clarify。**自定义输入显式可见**（choices 上限 4，无自动 Other——实测确认）：

```
question: "DP-001 token 有效期：建议 7 天。影响：用户 7 天后需重新登录。
  其他值（如 30 天）请选『自定义输入』并输入。"
choices:
  - "确认 7 天"                  # 业务选项 ≤3 个
  - "改为 1 天（更安全但频繁重登）"
  - "自定义输入（Other）"         # ← 第 4 位固定，显式可见
```

**choices 结构铁律**：业务选项 ≤3 个，第 4 位固定 `自定义输入（Other）`。备选超过 2 个时合并同类项或写进 question 文本，绝不让业务选项挤掉自定义项。

自定义输入捕获协议：
1. 用户选"自定义输入"或直接输入值 → 记录 value + reason（用户原话）
2. 同步回 spec 对应字段（如 DP-001 → behaviors B001 then 子句）
3. 确认记录标记 `result: modified`（不是 confirmed）
4. 开放式决策点（无法预设选项）→ 直接用无 choices 的 clarify

实现类批量授权：
```
question: "实现类决策点（DP-005 等 W 个）全部授权 AI 决定？"
choices:
  - "全部授权"
  - "逐个确认"
  - "自定义输入（Other）"
```
