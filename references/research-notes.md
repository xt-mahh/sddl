# SDDL 架构调研笔记规范（v2.0，research.md）

> 选型不拍脑袋：contract 级架构决策点（技术栈/存储/框架）alternatives ≥ 3 时，
> /sddl:arch 必须附调研笔记。产物落 `sddl/research/<topic>.md`，供 confirm 阶段引用。

## 触发条件

- 决策点 `category: contract` 且 `alternatives` 有 ≥ 3 个候选
- 或用户显式要求（任何决策点均可附调研）

不满足时跳过——避免为二选一的决策硬凑文档。

## 笔记结构（sddl/research/<topic>.md）

```markdown
# 调研：<topic>（对应 DP-xxx）

## 候选对比
| 维度 | 候选A | 候选B | 候选C |
|------|-------|-------|-------|
| 功能覆盖 | ... | ... | ... |
| 性能（附数据来源） | ... | ... | ... |
| 生态/维护活跃度 | ... | ... | ... |
| 团队熟悉度 | ... | ... | ... |
| 与 constitution 冲突 | 无 / P-00x | ... | ... |

## 数据来源
- [benchmark/文档/实测] 链接或命令，可复查

## 建议
推荐候选 + 理由（须能映射回对比表某几行，不接受表外理由）
```

## 硬规则

- 对比表至少 3 个维度，其中 ≥ 1 个有可复查的数据来源（链接/命令/实测记录）
- "与 constitution 冲突"行必填——候选违反项目宪法条款 = 直接出局
- 建议理由必须引用表内行号/维度，表外理由（如"我更熟"）写入团队熟悉度维度而非建议段
- 调研笔记不进质量门禁（不是 spec/artifact），但 confirm 阶段用户问"为什么选 X"时它是唯一证据
